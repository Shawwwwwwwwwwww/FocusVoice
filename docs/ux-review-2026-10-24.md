## 0. 结论速览

**总分：2.4 / 5**（现状）。逐项：触发交互 1.6，HUD 2.2，微调预览 2.3，设置面板 2.6，菜单栏 3.0，视觉体系 2.4。

五个关键判断：

1. **“时灵时不灵”不是长按时长问题，是判定架构问题。** 旧方案把“是否可输入”压在 `AXUIElementCopyElementAtPosition` + 30 层祖先回溯 + “窗口内容区一律放行”这三层启发式上（362–413、1828–1829），任何一层在 Electron/Chromium 懒加载 AX 树上返回 nil，都会**静默放弃**——没有 HUD、没有提示、没有日志。用户无法区分“没按够”与“按了但被拒”。
2. **最可靠的触发通道（Carbon 全局热键）被藏在“备用”位置。** `⌥Space` 不依赖 AX 命中测试、在任何 App 都成立（1843–1893），却只出现在菜单文案和设置副标题里；而主触发是一条成功率未知的手势。应当把“显式手势绝不静默失败”定为产品原则。
3. **HUD 目前不是“实时预览”，是“最后 24 个字的跑马灯”。** `setLiveTranscript` 只取 `suffix(26)`（1622），`updateElapsed` 取 `suffix(24)`（1632），且与计时文案互相覆盖；410×96 固定尺寸（1702）放不下一句中文。用户要的“边说边出字”在视觉上未成立。
4. **本地引擎也能做到“句级实时”。** 不必等待伪 token 流：录音侧已经有 16kHz PCM 流（646、792），配合 Silero VAD 切句 + SenseVoiceSmall（239 MB，CPU/M4 单句约 150–400 ms）逐句落字，首句 0.7–2 s 可见，结束零等待；whisper large-v3 则明确标注“说完出字”，不假装实时。推荐把 SenseVoice 设为默认引擎。
5. **推荐交互：主触发 = `⌥ + 单击输入框`（即时、显式、可吞掉冲突点击），备用 = `⌥Space` 开关；旧长按降级为默认关闭的“兼容模式”，保留 0.6 s + 光标旁蓄力环。** 双通道独立，任一通道失效时另一通道仍可用；所有显式手势都保证有可见结果（录音 HUD 或明确错误 + 剪贴板兜底）。

## 1. 触发失败根因剖析（为什么“点了没反应”）

| # | 根因 | 证据（v0.7.3 行号） | 影响 |
|---|---|---|---|
| R1 | 判定链**静默失败**：hit 为 nil 或祖先树 30 层内找不到 `AXWindow` 时直接 `return`，不产生任何 UI | 1828–1829、362–377 | 用户看到的就是“没反应”；Electron/Chromium AX 树懒加载时高发 |
| R2 | “窗口内容区一律可输入” | 410–413 | 标题栏下任意位置长按都会启动录音；在正文/图片/工具栏上也可能误触发；`start()` 不再复核可编辑性（1951–1956） |
| R3 | 固定 42 pt 标题栏假设 | 397–402 | Chrome 标签栏（≈40 pt）、自定义标题栏 Electron App（48–52 pt）会误判；带工具栏的 App 会把工具栏算进内容区 |
| R4 | 纯时间手势、零过程反馈 | 1774–1839 全段无任何绘制 | 1.2 s 内用户不知道“是否已被识别”，松手才见分晓；“手感”不可建立 |
| R5 | 6 px 位移容差 + 无拖拽事件监听 | 1780、1786（仅 down/up） | 触控板轻微抖动/按下时的 1 px 位移即取消；且只在 mouseUp 清状态，乱序时可能残留 |
| R6 | 判定在主线程同步做多次 AX IPC | 1819–1832 | Electron 上单次 `ElementAtPosition` 可达数十 ms，叠加 30 次 parent 查询，触发瞬间卡顿，进一步加剧“不跟手” |
| R7 | 粘贴**没有回读校验**却宣布成功 | 1410–1455、1597–1601 | 三段式注入后直接返回；失败（焦点丢失/AX 拒绝）时 HUD 仍显示“已插入文字”，文字实际没进输入框 → 用户认定“偶尔失灵” |
| R8 | 录音中/转录中错误提示位置漂移 | 2026、2139、2173（`show(.error)` 未传 anchor → 屏幕正中 1752–1757） | 错误提示与操作点脱节，用户找不到 |

**结论：** 不要在“长按 + 窗口树回溯”上继续加码（v0.7.3 已把回溯加到 30 层、阈值降到 1.2 s，问题依旧）。正确方向是：**用一次代价可控的焦点查询做“目标确认”，把用户显式手势作为触发许可，失败时给可见出口。**

## 3. 触发交互方案对比与推荐

### 3.1 候选定义

| 代号 | 方案 | 说明 |
|---|---|---|
| **A0** | 现状：任意位置长按左键 1.2 s + AX 判定 | v0.7.3 实现 |

### 3.2 评分矩阵（1–5，加权）

权重：触发成功率 30%、误触率 20%、学习成本 15%、冲突 10%、可发现性 10%、录音中可取消 5%、响应延迟 10%。

| 候选 | 成功率 | 误触率 | 学习成本 | 冲突 | 可发现性 | 可取消 | 延迟 | **加权分** |
|---|---|---|---|---|---|---|---|---|
| A0 现状长按 1.2 s | 2.0 | 2.0 | 4.5 | 4.5 | 3.0 | 3.0 | 2.0 | **2.78** |
| A1 改进长按 0.6 s + 环 | 3.5 | 3.5 | 4.5 | 5.0 | 2.5 | 4.0 | 3.5 | **3.73** |
| B1 双击 Fn | 5.0 | 4.5 | 2.5 | **1.5** | 1.5 | 5.0 | 5.0 | **3.83** |
| B2 双击 ⌥ | 5.0 | 4.5 | 2.5 | 4.0 | 1.5 | 5.0 | 5.0 | **4.08** |
| **C ⌥ + 单击** | **4.5** | **4.5** | 3.5 | 3.5 | 3.0 | 5.0 | 5.0 | **4.18** |

关键说明：

- **B1 冲突面最大**：系统听写可绑定为“连按 Fn”（系统设置 › 键盘 › 听写），Fn/🌐 还承担输入法切换与表情面板；拦截会与系统抢事件，非程序员遇到“系统听写和 FocusVoice 同时弹麦克风”会直接失去信任。**不推荐。**
- **B2 不冲突但不可发现**：双击 ⌥ 不与系统快捷键冲突，但没有任何系统入口能提示这个手势，用户只能被口头教会；判定需要 250–350 ms 窗口、失败时也无从自查，且与“按住 ⌥ 再单击”动作相似、容易混淆。**可作键盘党备选，不作主触发。**
- **C 的核心优势是“显式 + 即时 + 可吞掉副作用”**：`⌥` 表示“这是语音指令”，单击给出明确目标；触发时只需一次焦点查询（focused element）即可确认可编辑性；配合 CGEventTap 可吞掉该次点击，避免 VS Code “⌥点击加多光标”、浏览器 “⌥点击链接下载” 等副作用。失败时因手势是显式的，可按“允许启动 + 剪贴板兜底”处理，**绝不出现按了没反应**。
- **A1 定位为兼容模式**：保留 0.6 s + 蓄力环能安抚旧习惯，但“按住不动 0.6 s”本身在阅读/等待时仍可能误触；且它继续依赖 hit-test。因此**不作为默认主触发，但保留开关**。
- 组合可靠性：C 与 `⌥Space` 是两条独立链路（前者依赖 AX 焦点、后者完全独立），同时失效概率趋近于 0。

| **备用触发** | `⌥Space` 开/关 | 常开 | 原有习惯；不依赖 AX；任何 App 可用 |

### 3.4 触发判定伪代码（CGEventTap 版本）

```swift
// 事件源：CGEventTap(.defaultTap)（需辅助功能授权）；创建失败时退化为 NSEvent 全局监听，但失去“吞事件”能力
// 说明：AX 查询全部带 40ms 预算；超时按 unknown 处理，绝不阻塞主线程超过 40ms

enum Verdict { case editable, blocked, unknown }

func onLeftMouseDown(_ p: CGPoint, _ flags: CGEventFlags) -> Bool /* return true = 吞掉事件 */ {
    guard idleOrRecording else { return false }

    // 1) 录音中：任何触发手势 = 结束（提交）
    if state == .recording {
        finish(reason: .userCommit)
        return true
    }

    // 2) ⌥ + 单击（主触发）
    if flags.contains(.maskAlternate), prefs.optionClickTrigger {
        let focused = AX.focusedElement()                       // 单次查询，≤40ms
        let hit = AX.hitTest(p)                                 // 单次查询，≤40ms
        let verdict = InputDetector.verdict(hit: hit, focused: focused, point: p)

        switch verdict {
        case .editable:
            let shouldSwallow = (hit === focused)               // 已在该输入框内：吞掉，避免多光标/下载
            beginSession(anchor: AX.caretRect(focused) ?? AX.frame(hit) ?? p,
                         target: AX.isEditable(focused) ? focused : hit)
            return shouldSwallow
        case .unknown:                                          // Electron 懒加载 AX / 超时
            // 显式手势绝不静默失败：仍启动，锚鼠标；结束时无目标则复制兜底
            beginSession(anchor: p, target: nil)                // HUD 标记“目标未知”
            return false                                        // 不吞，避免破坏应用自身点击
        case .blocked:                                          // 标题栏/按钮/滚动条/桌面
            showTransientHint("这里不能输入文字 · 点输入框或按 ⌥Space", 1.4)
            return false
        }
    }

    // 3) 长按兼容模式（默认关闭）
    if prefs.holdToTalkEnabled {
        let v = quickVerdict(p)      // 仅做 blocked 判断（标题栏/按钮/滚动条/桌面），预算 40ms
        if v != .blocked {
            armHold(p, verdict: v)   // 80ms 显示蓄力环；holdDelay 提交；位移 >4pt 或 mouseUp 取消
        }
        return false
    }
    return false
}

func beginSession(anchor: CGPoint, target: AXUIElement?) {
    let id = UUID()
    session = Session(id: id, anchor: anchor, target: target, startedAt: .now)
    HUD.show(.preparing, anchoredAt: anchor)                    // ≤100ms 可见
    Task {                                                       // 权限 + 音频启动
        guard await ensureMicPermission() else {
            HUD.show(.failure(.micPermissionDenied, recovery: .openSettings), anchoredAt: anchor)
            return
        }
        do {
            try await recorder.start(source: prefs.audioSource)
            guard session?.id == id else { return }              // 迟到回调必须校验
            HUD.show(.recording(startedAt: .now), anchoredAt: anchor)
            startRecognizerStream(for: id)
            installGlobalKeys()                                  // Esc=取消, ↵/⌥Space=提交
            scheduleWarning(at: 270); scheduleCap(at: 300)
        } catch {
            HUD.show(.failure(.audioStartFailed(error), recovery: .retryOrSettings), anchoredAt: anchor)
        }
    }
}
```

**判定规则（`InputDetector.verdict`）**

```
blocked  = role/subrole ∈ {AXCloseButton, AXFullScreenButton, AXMinimizeButton, AXScrollBar,
                           AXToolbar, AXTitleBar, AXMenu, AXDock, AXSplitter}
         | secureTextField（含祖先）
         | 命中窗口标题栏矩形（动态取得，兜底 top 42pt）
         | 桌面（Finder 且无窗口标题 / AXScrollArea 全屏）
editable = hit 或 focused 的角色 ∈ {AXTextField, AXTextArea, AXSearchField, AXComboBox(可编辑)}
         | AXEditable == true
         | focused 元素 frame 包含点击点
unknown  = AX 查询超时 / hit == nil / 角色为空
```

规则：`blocked` 才拒绝；`unknown` 允许启动（显式手势）；长按模式下 `unknown` 也允许，但环呈中性灰，提交时转为“目标未知”标记。

### 3.5 蓄力环（兼容模式）规格

| 项 | 规格 |
|---|---|

### 3.6 完整状态机

**状态表**

| 状态 | 进入条件 | HUD | 可接受事件 |
|---|---|---|---|
| `idle` | 初始/收尾完成 | 隐藏 | ⌥click、⌥Space、长按蓄力（兼容） |
| `arming` | 长按按下 | 蓄力环 | mouseUp/位移（→idle）、holdDelay（→preparing） |
| `preparing` | 触发提交 | “正在启动录音…”，可取消 | Esc/取消（→cancelling）、成功（→recording）、失败（→failure）、5 s 超时（→failure） |
| `recording` | 音频已启动 | 录音 HUD + 实时文本 | Esc（→cancelling）、↵/⌥Space/再次⌥click（→finalizing:commit）、静音自动结束（→finalizing:autoEnd）、300 s（→finalizing:cap）、音频错误（→failure） |
| `finalizing` | 停止采集 | “正在整理文字…”，可取消 | 已有 confirmed 文本（→delivering，0 等待）、识别完成（→delivering）、20 s 超时（→failure.timeout）、Esc（→cancelling） |
| `delivering` | 得到文本 | 保持 finalizing 视觉 | 注入成功（→success）、未验证（→success.shared）、失败（→failure.noTarget）、Esc 取消（丢弃） |
| `success` | 注入完成 | 34 pt 胶囊“已插入 · ⌘Z 撤销” | 1.1 s 自动 →idle；⌘Z（可选 → 撤销插入） |
| `failure` | 任一失败 | 错误 HUD（4 s，hover 暂停） | 行动按钮、Esc、重试 |
| `cancelling` | Esc/✕ | 100 ms 淡出 | —（删除临时文件、不上传、不改剪贴板） |

**事件处理伪代码（关键分支）**

```swift
func onEsc() {
    switch state {
    case .idle, .success, .failure: HUD.hide()
    case .arming: cancelArming()
    case .preparing, .recording, .finalizing, .delivering: cancelSession()
    }
}

func cancelSession() {
    let id = session?.id
    session = nil
    recognizeTask?.cancel(); recorder.cancel(); stream.stop()
    removeTempFiles()
    // 不写剪贴板、不粘贴、不播成功音
    HUD.hide(after: 0.1)
    log(.cancelled, id)
}

func finish(reason: FinalizeReason) {
    guard state == .recording else { return }
    let id = session!.id
    let confirmed = recognizer.confirmedText
    state = .finalizing
    HUD.show(.finalizing(detail: engine.shortName), anchoredAt: session!.anchor)

    if !confirmed.isEmpty {                  // 句级流式已拿到全文 → 零等待
        deliver(text: confirmed, id: id); return
    }
    recognizeTask = Task {
        do {
            let text = try await recognizer.flush(timeout: 20)
            guard session?.id == id else { return }
            guard !text.trimmed.isEmpty else {
                fail(.noSpeech, id: id)      // 无文字兜底
                return
            }
            deliver(text: text, id: id)
        } catch is CancellationError {
            return
        } catch {
            guard session?.id == id else { return }
            fail(.recognitionFailed(error), id: id)
        }
    }
}

func fail(_ kind: FailureKind, id: UUID) {
    guard session?.id == id else { return }
    var recovery: Recovery = .none
    switch kind {
    case .noSpeech:
        // 不覆盖剪贴板、不自动粘贴，给“重说/关闭”
        recovery = .retryOrDismiss; HUD.show(.failure(.noSpeech, recovery), autoHide: 3)
    case .noTarget:
        // 文本已复制，用户自取
        recovery = .pasteManually;  HUD.show(.failure(.noTarget, recovery), autoHide: 4)
    case .micPermissionDenied:
        recovery = .openSettings;   HUD.show(.failure(kind, recovery), autoHide: 4)
    case .timeout:
        recovery = .retryOrCancel;  HUD.show(.failure(kind, recovery), autoHide: 4)
    default:
        recovery = .retry;          HUD.show(.failure(kind, recovery), autoHide: 4)
    }
    state = .failure; log(kind, id)
}

// VAD 自动结束（仅外录 + 仅 SenseVoice/腾讯云 + 设置开启）
func onPCM(_ pcm: Data) {
    guard prefs.autoFinishOnSilence, recorder.currentSource == .mic else { return }
    let speech = vad.ingest(pcm)             // Silero VAD（无模型时用 RMS > 0.02 兜底）
    if speech { heardSpeech = true; lastSpeechAt = .now; cancelEndCountdown() }
    else if heardSpeech,
            Date().timeIntervalSince(lastSpeechAt) >= 2.0,
            Date().timeIntervalSince(recordingStartedAt) >= 0.8 {
        startEndCountdown(0.5)               // 计时区显示 0.5s 收缩环
    }
}

func onAnyKeyOrMouseDuringCountdown() {   // 用户还在思考/停顿
    cancelEndCountdown()                  // 任意输入即取消自动结束
}
```

### 4.2 本地“边说边出字”的实现策略（关键）

结论：**不要追求 token 级流式，做“句级流式”即可满足用户感知**，且实现成本低。

- 录音侧已经产出 16 kHz/16-bit/mono PCM 分片（`BuiltInMicRecorder.onPCMChunk` 646、`TencentStreamRecognizer.sendPCMChunk` 792），可直接复用。
- 分帧 20 ms；VAD：优先 Silero（`.dsh-ref` 中已有 `silero_vad.onnx` 可用资产），无模型时用 RMS 阈值兜底（阈值 0.02，与既有 `trackSilence` 一致）。
- 切句参数：`preRoll 250ms / minSpeech 350ms / trailingSilence 450ms / maxSegment 12s`。
- 每句完成 → **立即**送入 SenseVoice 识别 → 追加到 `confirmed`；正在说的这一句在 HUD 上显示 partial 占位：`倾听中…`（60% 白 + 呼吸点），不伪造文字。
- 结束（用户提交/静音自动结束）时：把最后不足一句的尾巴补识别一次，拼接 → 零等待注入。
- whisper large-v3：同一 VAD 框架，但**不要**逐句跑（单句 1.5–3 s，边录边转会排队追不上说话）；改为录音中只显示“高精度 · 说完出字”，结束一次性转写。若未来启用逐句，必须串行且丢弃过期段。

### 4.6 键盘与焦点

- `Esc`：取消（录音/整理/预览通用），全局监听，不要求 HUD 为 key。
- `↵` 与 `⌥Space`：提交。两者同时存在，照顾“打字习惯”和“旧习惯”。
- `⌘Z`：插入后 1.1 s 内可撤销（可选，P2；利用目标 App 自身撤销栈会插入一条编辑历史，需谨慎，建议只做提示不做自动撤销）。
- HUD 永远不抢焦点（`canBecomeKey = false` 保持），因此所有键走全局监听；监听到 `↵` 时**不吞事件**（让目标 App 也能收到？——不，提交瞬间吞掉，避免聊天框被发送空消息；规格：提交键吞掉）。

### 4.7 错误与兜底态原则

1. 错误位置 = 操作位置（HUD 锚点），不得飘到屏幕中央。
2. 错误文案 = 用户语言（发生了什么 + 我该做什么），不出现 HTTP 状态码/异常类名。
3. 每个错误至少一个行动按钮：打开设置 / 重试 / 复制 / 关闭。
4. 错误自动消失前必须“hover 暂停”，且日志保留细节供诊断。
5. 绝不谎报成功（回读校验）。

## 6. 交互验收标准（用户可感知的行为断言）

> 每条都应能被非程序员用“看得见/听得到”的方式判定。P0 项必须全过才可发布。

### 触发与可靠性

- **AC-01 主触发即时性（P0）** 在 Chrome、ChatGPT Desktop、微信、飞书、TextEdit、Pages 六个目标中各做 10 次 `⌥+单击` 输入框：HUD 从点击到可见 **p95 ≤ 120 ms**，成功进入录音 **20/20**。
- **AC-02 主触发不静默（P0）** 在 Electron 的深层输入框中 `⌥+单击`：即使 AX 判定失败，用户也必须在 300 ms 内看到 HUD（标题含“目标未识别”），不得出现“点了没反应”。
- **AC-03 备用通道（P0）** 在任意 App（含全屏视频、游戏、远程桌面）按 `⌥Space`：**50/50** 开始录音；再按一次结束并插入；全程不依赖鼠标位置。
- **AC-04 零误触（P0）** 分别做 10 次：拖动标题栏、拖选正文、拖滚动条、点桌面空白、点工具栏按钮、拖图片 —— 录音启动次数必须为 **0**；`⌥+单击` 这些区域时给出 1 行提示且不录音。
- **AC-05 长按兼容模式（P1，开启时）** 按下后 **≤100 ms** 出现光标旁蓄力环；位移 >4 pt 环消失且 0 次录音；按满 0.6 s 环填满，松手前 HUD 已出现；环在任何屏幕边缘都完整可见。
- **AC-06 取消（P0）** 录音中按 Esc 或点 ✕：HUD 300 ms 内消失，**0 次粘贴**，剪贴板内容与录音前完全一致，临时文件被清理。
- **AC-07 提交（P0）** 录音中按 `↵` 或 `⌥Space`：1 s 内 HUD 进入“已插入”；目标输入框出现文字。
- **AC-08 插入失败兜底（P0）** 人为让目标输入框失焦（录音中点击桌面）后提交：HUD 显示“已复制 · 按 ⌘V 粘贴”，且剪贴板含完整文本；**不得**显示“已插入”。

### 实时预览

- **AC-09 腾讯云首字（P0）** 0.8 s 内 HUD 出现首字；说话过程中 confirmed 持续增长，HUD 至少可读 2 行（≥ 40 个汉字），不再是末尾 24 字的跑马灯。
- **AC-10 SenseVoice 句级流式（P0）** 连续说 3 句（每句间停顿 0.6 s）：每句结束后 **≤2.5 s** 该句以 confirmed 形式出现；结束后 **≤1 s** 完成插入（零等待）。
- **AC-11 whisper 诚实标注（P1）** 使用 whisper 引擎时，录音中显示“高精度 · 说完出字”与电平，不显示伪造的 partial；结束后 3 s 内出字。
- **AC-12 partial/confirmed 可辨（P0）** 距离屏幕 50 cm 观察：confirmed 与 partial 在颜色深浅和光标标记上均可区分；强制“提高对比度”后 partial 亮度自动提高到 ≥75%。
- **AC-13 长文可读（P1）** 连续说 60 s（约 300 字）：HUD 最多 4 行、自动滚动到最新内容、宽度不超过 560、不遮盖插入行。
- **AC-14 空结果（P0）** 静音 3 s 后提交：显示“没听清，再说一次吧”，不覆盖剪贴板、不粘贴、无系统弹窗。

### HUD 与窗口

- **AC-15 多屏不出屏（P0）** 在双屏（左右排列 + 上下排列各一次）的四角触发：HUD 完整可见，距屏幕边缘 ≥12 pt，不跨屏，不压在菜单栏/Dock 下。
- **AC-16 不遮插入行（P0）** 在屏幕底部输入框触发：HUD 自动翻到插入行上方；在顶部输入框触发：自动翻到下方。
- **AC-17 状态可见（P0）** 录音中 3 秒不说话：电平柱呈低平状态，计时递增；说话时电平柱明显跳动 —— 用户能区分“在录但没声”和“没在录”。
- **AC-18 成功不谎报（P0）** 见 AC-08；另外“已插入”状态停留 ≥1 s，肉眼可读。
- **AC-19 错误可行动（P0）** 拔掉麦克风权限后录音：HUD 显示原因 + “打开设置”按钮；点击直接打开对应系统设置页。
- **AC-20 转录可取消（P1）** 使用 whisper 第一次识别（冷启动 5–10 s）时按 Esc：300 ms 内 HUD 消失，0 次插入，且可以立刻重新触发录音。
- **AC-21 5 分钟上限（P2）** 录音到 4:30 时计时变色并有文案预告；5:00 自动提交并提示。

### 设置

- **AC-22 首屏主路径（P1）** 打开设置 720×560：不改默认、换主引擎、开/关预览三个操作全部在首屏完成，无需滚动。
- **AC-23 引擎状态真实（P0）** 未配置腾讯云密钥时，设置与菜单栏的“腾讯云”均显示“未配置”且不可作为当前引擎；配置后 3 s 内“保存并测试”给出连接结果。
- **AC-24 无死控件（P0）** 逐个切换设置面板所有开关/选择：每一项都能在 HUD/行为上观察到即时变化；不存在“改了没反应”的控件（特别是剪贴板相关）。
- **AC-25 窗口行为（P1）** 设置窗口可缩放、可记忆位置；`⌘W` 关闭后 `⌘,` 重新打开并恢复上次页。

### 菜单栏与文案

- **AC-26 状态栏状态（P1）** 状态栏图标在空闲/录音/识别中三种状态可在 1 m 外分辨；悬停 tooltip 显示当前状态与计时；VoiceOver 能读出“FocusVoice，正在录音”。
- **AC-27 最近转写反馈（P2）** 点击任一条历史：菜单关闭后 1.2 s 内出现“已复制到剪贴板”提示，`⌘V` 可粘贴。
- **AC-28 术语零暴露（P1）** 默认可见界面（HUD、菜单栏、设置首屏、状态文案）不出现 `whisper.cpp`、`Metal`、`ScreenCaptureKit`、`TC3`、`1.5 秒`、`30 层` 等实现术语。

## 8. 附录

### A. 与并行实现的衔接说明

评审期间工作区 `FocusVoice.swift` 已被并行修改（行数从 3404 增至 3800+，已出现 SenseVoice 资产定位、蓄力环 HUD、`⌥+单击`、confirmed/partial、RMS 静音自动结束等）。本文**不评价进行中的代码**，只提供目标规格。实现时最容易被漏掉的 10 条（按 §6 自检）：

1. `⌥+单击` 在 AX 判定失败（nil/unknown）时仍要启动并给“目标未识别”，不能静默 `return`。
2. 吞掉“已在焦点输入框上的 ⌥+单击”，否则 VS Code 会加多光标、浏览器会下载链接。
3. `⌥+单击` 的副作用处理需要 CGEventTap；仅 `NSEvent.addGlobalMonitor` 无法吞事件。
4. 长按兼容默认关闭；`requireEditableTarget` 默认应为 true（当前若为 false，0.6 s 会回到 v0.7.3 的“内容区全放行”误触）。
5. 蓄力环必须做屏幕边界翻转，否则屏幕右下角触发时环被裁掉。
6. 静音自动结束仅对外录 + 流式引擎生效；内录（会议/视频）必须关闭，否则停顿即误结束。
7. HUD 的错误态必须带锚点，不能回落到屏幕正中。
8. 插入后必须回读校验，未验证时显示“已复制 · ⌘V”，不得显示“已插入”。
9. HUD 固定尺寸与硬编码白色/透明度要改成语义色 + `vibrantDark`，否则亮色桌面、提高对比度、降低透明度下都不可读。
10. 所有显式手势（含 ⌥Space）在 `preparing` 阶段必须有取消入口与 5 s 超时。

### D. 一句话总结

把“长按 + 猜窗口”换成“**⌥ 点击 + 确定目标 + 可见反馈**”，把“末尾 24 字跑马灯”换成“**confirmed/partial 双色四行 + 句级流式**”，设置从“卡片说明书”换成“**状态即控件、布局即解释**”——用户感知到的就是：**一按就录、边说边看、说完即得、失败有路**。
